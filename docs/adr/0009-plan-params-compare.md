# ADR-0009：AI案をパラメータつきで残し、AI案どうしを比べる

- 日付：2026-10-12
- 状態：採用

## 背景
デモ期間の AI案の画面は「手作業案（予定画面の割当）とAI案」を並べていた。デモの手作業案は seed が機械的に作った架空の割当で、比べても意味が薄い。
見たいのは、最適化の重み・制約を変えたときに割当と順番がどう変わるか。

## 選択肢
1. 案A：手作業案とAI案の比較のまま、パラメータだけ画面で変えられるようにする
2. 案B：AI案ごとにパラメータを残し、同じ日の任意の2つのAI案を並べる。手作業案は seed で作らない
3. 案C：パラメータの掃引（多数の組み合わせ）を自動で回して表にする

## 決定
案B。
- パラメータ（`planParamsSchema`）：待ち時間の重み・訪問のあいだの余裕（分）・1人の件数の上限・移動時間の求め方（Google／概算）。最適化サービスの既存の契約（`weights.waitSeconds`・`minGapBeforeMinutes`・`maxVisits`）に対応させ、契約は変えない
- プリセット3種（`PLAN_PRESETS`）：標準・移動最短・ゆとり・件数ならし。第1プリセット（標準・概算）が既定
- `createPlanRun` は `params` を受け取り（省略は既定）、`planRuns` に `params`・`presetId` と結果を組で残す
- AI案の画面できょう以降の日を開いて、その日のAI案が無ければ第1プリセットで自動で作る（`assign_and_order` の事業所だけ）。その日の割当が何も無ければ、その案を予定にする（`manualPlans` と、AI案に入った訪問の `visits.staffId`。`fromRunId` に元の案）
- 移動時間の求め方（`mapsApi`）の既定は事業所の設定 `useMapsApi`。画面で変えると設定も変わる（実測区間の予測も同じ設定を使う）
- 画面で任意の2案（案A・案B）を選び、パラメータ・指標・担当ごとの順番・地図を並べる。どの案でも「この案を予定にする」で予定に書ける
- seed は訪問と稼働時間帯だけを入れ、担当（手作業案）は入れない

## 理由とトレードオフ
- 得るもの：パラメータと結果の対応が記録に残り、あとから比べ直せる。スタッフ画面は採用したAI案で動く
- 失うもの：画面上の「手作業案とAI案」の比較（PRD の削減率 KPI の見せ方）。手作業案がある日は従来どおり `metrics.manual` を残すので、実証データ CSV の計画値比較は出せる。予定がAI案を採用したものだった実行は `manualFromRunId` を残し、CSV の計画値比較から外す
- 自動作成は1時間20回の上限に数える。日付を次々に開くと上限に届きうる

## 影響
- design.md の planning の責務・持つデータに、パラメータと AI案どうしの比較、予定への採用を足した
- 予定への採用は画面からの直接書き込み（予定画面の保存と同じ書き込み・同じルール）。改修版の `decidePlan`（理由つきの決定）とは別
- 協力法人の実データ（手作業の割当がある）で手作業案との比較が要るときは、比較の片側に手作業案を選べるようにする
