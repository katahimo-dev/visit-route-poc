| 交通費 | 作らない | 自作GASで距離×10円/km | 移動実績から自動算出できる（安い追加） |

### 選択肢

| 案 | 中身 | AI | 長所 | 短所 |
|---|---|---|---|---|
| A 提案書どおり | 移動時間予測＋1人1日の**順番**最適化＋ジオフェンス勤怠 | 予測ML、順番最適化 | 提案書・KPIと完全一致 | alcaでは順番が動かず、AI案＝手作業案になりやすい（効果が出ない） |
| **B 推奨：割当＋順番** | ジオフェンス勤怠・予実を土台に、AIは①移動時間予測 ②**訪問の割当と順番の最適化**（時間枠付き配送計画問題 VRPTW）。事業所ごとに「順番だけ」「割当も」を切替 | 予測ML、組合せ最適化（同じソルバーで両モード） | シッター（順番が動く）にもalca（割当が動く）にも効果が出る。KPI「移動時間20〜30%削減」をそのまま測れる。提案書の「AI組合せ最適化」の範囲内 | 提案書で次年度とした「配置」に一部踏み込む（市への説明が要る）。制約（性別・NG・勤務曜日）の登録が増える |
| C 予実・請求寄り | 予実管理＋勤怠＋移動支援の明細出力。AIは記録の音声→文章化 | 生成AI | alcaの最大の負担に直撃 | 提案書のKPI（訪問効率・予測精度）から外れる。様式が市町村別で重い。10-08要件で「作らない」に明記 |

**決定：B**（2026-10-10）。理由：同じ地図API・同じソルバーで「手作業案 vs AI案」の計画値比較ができ、KPIと実証デザインを変えずに、alcaで効果が出ないリスクを消せる。勤怠・予実・交通費はalcaの優先度Aに沿い、位置情報の取得理由（スタッフへの説明）にもなる。

以下の要件は B を前提に書く。

## 1. 背景と課題

訪問型対人サービス（シッター・家事代行／障害福祉・介護／訪問看護・リハビリ）では、スタッフが自宅から直行直帰し、訪問先が市内に分散している。

- 管理者：だれをどこへ、どの順で行かせるかを手作業（Googleカレンダー・Notion）で組んでおり、移動のむだと組み直しの手間が大きい。
- スタッフ：入退の報告をLINEで送っており、実働・移動・休憩の記録が残らない。事業所は「長時間働かせていない」ことを示せない。
- 事業所：予定と実績のズレ（3時間予定→2時間実績）が月初の突合まで見えない。

本PoCは、仙台市「先端テクノロジー・データ利活用ユースケース創出支援事業」の実証（3事業所×4件＝12件、2回構成）で、協力法人に実際に使ってもらうためのアプリである。

## 2. 対象ユーザー

| 役割 | 説明 | 主な目的 |
|---|---|---|
| スタッフ | 訪問するシッター・ヘルパー・看護師等（主に50代女性、本人のスマホ） | きょうの順番を見る、はじめる・おわるを押す |
| 事業所管理者 | 各協力法人のシフト担当・事務 | 予定を登録し、手作業案とAI案を比べて決める。勤怠を承認する |
| 実証運営者 | キューテスト（中原・藤野）・松浦 | 事業所の開設、実証データのCSV出力・分析 |

## 4. やらないこと（スコープ外）

- 請求（国保連・移動支援の市町村別明細）、実績記録票の電子化・利用者サイン
- 業種別の記録テンプレート、日報・カルテの生成AI（案D-3「きろく」画面は対象外。§8で確認）
- 給与計算、既存の勤怠・給与・請求システムとのAPI連携、勤怠の自動確定
- 急なキャンセル・追加時の自動再配置、LINE連携、空き枠の可視化
- 相性の学習（相性は「NG」の登録のみ）
- 月次シフトの一括自動作成（AI案は「1日単位」。月の比較は日の積み上げで出す）
- ウェアラブル連携、ネイティブアプリ（PWAのみ）

## 5. 成功の指標

| 指標 | 目標 | 測り方 |
|---|---|---|
| 訪問効率（TTS・総移動時間） | 20〜30%改善 | 同じ日・同じ訪問の手作業案とAI案を同じ地図APIで再計算（計画値比較）。実測を副として併記 |
| 移動時間予測の精度 | 誤差±10分以内の割合 90%以上（MAPE 15%以下を併記） | 予測値とジオフェンス実測の比較 |
| ルート作成・調整の手間 | 現行より削減 | ルート作成時間、手直し回数、AI案の採用率 |
| 使いやすさ | スタッフ5段階評価 平均4.0以上 | 実証後アンケート |
| 記録の完全性（運用） | 訪問の95%以上で到着・退出が記録される | 予定件数に対する実績件数 |

## 7. 制約

- 期限：10-08要件ではα版提供＝10月中旬・1回目＝10月下旬〜11月上旬。改修版＝12月中旬。事業終了 2027-02-28、報告 3/12
- 予算：地図API・AI利用料 220,000円／クラウド 30,000円（6か月）。開発 150h（松浦）
- 使う技術：Firebase（Hosting・Authentication・Firestore・Cloud Functions）、Google Maps Platform、PWA。最適化ソルバー（OR-Tools）は Python が必要 → Cloud Functions（Python）または Cloud Run
- 端末：スタッフ本人のスマホのみ（追加機器なし）。iPhone・Android
- 法規・セキュリティ：事業所間のデータ分離。位置は勤務中のみ・計測中を表示・生データは実証後に削除。氏名・住所と分析用IDを分け、開発側へは仮名データ。要配慮個人情報（障害・病状）は持たない
