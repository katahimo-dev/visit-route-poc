# ADR-0003：最適化は OR-Tools Routing（Python）で VRPTW として解く

- 日付：2026-10-10
- 状態：提案

## 背景
ピボット案B（PRD §0）で、最適化の対象を「1人の順番」から「事業所1日の割当＋順番」に広げた。時間の約束・勤務時間・性別希望・NG を絶対条件として守り、1事業所1日を30秒以内、同じ入力で同じ結果を返す必要がある。提案書は「古典ソルバーを実運用、QUBO・量子アニーリングはオフライン比較」。

## 選択肢
1. 案A：OR-Tools Routing（時間枠付き配送計画問題の標準機能）を Python で、Cloud Functions 2nd gen（Python）に置く
2. 案B：CP-SAT で自前に定式化する（10-08要件の記載）
3. 案C：TypeScript で自作ヒューリスティック（最近傍＋2-opt）

## 決定
案A。順番だけのモードは、各訪問の担当を手作業案に固定して同じソルバーで解く。CP-SAT・最近傍法・局所探索・QUBO＋SA／量子アニーリングは、同じ入力（planRuns の保存データ）を使う比較手法として `analysis/` でオフライン実行する。

## 理由とトレードオフ
- 得るもの：時間枠・勤務時間・割当可否（性別・NG）が標準の制約で書ける。工数が最小。
- 失うもの：Python のコードベースが1つ増える。Routing の探索は時間打ち切りだと結果がぶれるため、解の数で打ち切り・単一スレッドにする（時間はかかる側に倒れる）。

## 影響
- optimizer は状態を持たず、契約は docs/api/openapi.yaml の `SolvePlan` だけ。
- 見直す条件：8人×30件で30秒を超える、または再現性が取れない場合は CP-SAT（固定シード・単一ワーカー）に切り替える。
