# ADR-0002：位置計測は PWA の前景計測＋ボタン時点とする

- 日付：2026-10-10
- 状態：提案

## 背景
提案書は「追加機器なし・スマホのみ」。10-08要件は「勤務中だけ計測、計測中が見える」「ジオフェンスで到着・退出の候補（T3）」。PWA（ブラウザ）は画面を閉じると位置を取れない（特に iOS）。ネイティブのジオフェンスはアプリ配布が要る。

## 選択肢
1. 案A：PWA。勤務中はアプリを開いている間 `watchPosition` で計測し、端末側で訪問先との距離から到着・退出を判定。閉じていた間は「はじめる」「おわる」の時点の位置と時刻で補う
2. 案B：Capacitor でネイティブ化し、OS のジオフェンス・バックグラウンド位置を使う
3. 案C：位置は取らず、ボタンの時刻だけ

## 決定
案A（α版）。1回目の先行試験で精度が足りなければ、改修版で案B を検討する。

## 理由とトレードオフ
- 得るもの：ストア審査・配布が不要。iPhone・Android 同じコード。計測している時間が画面で明確（説明しやすい）。
- 失うもの：画面を閉じている間の到着は取れない → T3 と実測移動時間に欠損・補完が出る。補完した記録には印を付け、KPI 集計で区別する。

## 影響
- 「はじめる」で必ず位置と時刻を取り、到着候補が無ければ「はじめる」時刻を到着として補う（補完フラグ）。
- 移動時間予測の学習には、補完していない区間だけを使う。
- 見直す条件：先行試験で、到着・退出が実測できた訪問が 70% 未満。
